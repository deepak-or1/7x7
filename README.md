# Seven by Seven

A trail map of San Francisco and the whole Bay Area: 166 places in six regions (the City 38, Marin 25, East Bay 39, Peninsula 25, South Bay 15, North Bay 24), from Cloverdale to Gilroy, each cut into the sections locals actually name. Walk them, log the restaurants, bars and views you find, and keep the flags.

It also covers the Las Vegas Strip: a seventh region of five stretches from the STRAT to the Welcome sign (North Strip, Wynn & Venetian, Center Strip, CityCenter & MGM, South Strip), with the resorts as their 32 sections. It is drawn as one ribbon along Las Vegas Boulevard, a colour per stretch, with the resorts, the landmarks and the four big cross streets on it from the first view. Las Vegas is an *away* region: it sits at its true position, 600 km outside the Bay canvas, and the map cuts to it instead of flying there. A switch on the map (Bay Area | Las Vegas) goes between the two, and the app opens in the one it was left in.

It is a static site: no build step, no framework.

## Run it

Open `index.html` through any static server (opening the file directly works for everything except place search and the web manifest):

```
python3 -m http.server 8123
```

## Host it

The repo ships a GitHub Pages workflow (`.github/workflows/pages.yml`). Once, in the repository settings, set **Pages → Source** to **GitHub Actions**. Every push to `main` then deploys; the workflow can also be run by hand from the Actions tab. A hosted copy is what lets the "Where am I?" button use the phone's location, which browsers block inside an embedded frame.

| Path | What it is |
| --- | --- |
| `index.html` | the shell |
| `css/app.css` | all styling, light and dark |
| `js/map.js` | the canvas map: camera, gestures with inertia, terrain cache, labels, landmarks, hit testing; one camera box per area (the Bay canvas, and each away region) |
| `js/map3d.js` | the 3D map (beta), a second map engine with the same members and options as `js/map.js`: plateau blocks, landmark models, a camera that tilts as it zooms, names and spots on a 2D canvas above the scene. Off by default: the "3D map (beta)" switch under Settings, or `?map=3d` / `?map=2d` in the address. Always loaded but inert until `index.html` also loads three.js (0.160.0 from cdnjs, checked against its hash, never vendored) and `js/map3d/`; without them, or without WebGL, the app makes the flat map |
| `js/map3d/` | loaded only with the 3D map: `land.js` (block outlines and the land's meshes), `relief.js` (the land's real shape: each block's top is the real ground, read from `terrain.js`; without either file, or with `?m3d-land=flat`, the blocks are flat-topped plateaus), `terrain.js` (two height grids, the bay at about 250 m and San Francisco at about 40 m; generated by `tools/terrain3d.js`, do not edit by hand), `models.js` (bridges, landmarks, skylines, the flag and the bookmark), `fabric.js` (the city fabric that stands on the blocks close in: small buildings on a street grid, trees and lawn in the parks, made in chunks as the camera comes near and tinted from each block's colour), `air.js` (the light of the hour, the sky, the moving water and its wash, the fog bank, the ferries), `blocks.js` (the block outlines worked out ahead of time; generated by `tools/blocks3d.js`, do not edit by hand) |
| `js/app.js` | state, the region › place › section › spot hierarchy, logbook views, logging, storage |
| `js/sheet.js` | the phone bottom sheet |
| `js/geom.js` | projection, point-in-polygon, the Voronoi cut that sections a place |
| `js/glyph.js` | renderer for the 2.5D landmark glyphs |
| `js/places.js` | place search (Photon, OpenStreetMap data) |
| `js/link.js` | a pasted Apple or Google Maps link in search: read for its place, a short link through the link helper |
| `helper/` | the link helper (`link-helper.js`, a Cloudflare Worker) that reads the full link behind a short Maps link; see `helper/README.md` |
| `js/sync.js`, `js/sync-config.js` | the shared logbook on the hosted site |
| `js/photos.js` | photos on spots, sections and places (hosted site): downscale, capture date from EXIF, cache, the photo hero at the top of a panel (a section or place also shows the photos of what is inside it) and the lightbox (swipe, pinch and double-tap zoom, swipe down to close, a thumbnail strip to reorder, delete, crop and rotate); stored beside the log at `logs/<key>-ph` (full photos), `logs/<key>-pt` (480 px thumbs) and `logs/<key>-po` (the chosen order, first is the cover), with a copy in IndexedDB |
| `js/streetmap.js` | the street map in a spot or section panel (hosted site): OpenFreeMap vector tiles in the app's palette, one shared map, its library loaded once the first place, section or spot has opened, Google's embed as the fallback |
| `js/lookback.js` | looking back: repeat visits on a spot (`spot.visits`, with `spot.at` the latest), the timeline by month, the "on this day" card on the first screen, and the recap of a month or a year, shared as a 1080 x 1350 PNG |
| `vendor/` | MapLibre GL JS 5.24.0 (BSD-3-Clause, licence in `vendor/LICENSE-maplibre-gl.txt`), used only by `js/streetmap.js` |
| `data/geo.js` | boundaries and the projected canvas (generated by `tools/geo-build.js` from `tools/geo-places.json`; do not edit by hand). Away regions are listed under `away` in the places file with their Census state; a place that is no Census place (a stretch of the Strip) carries its own polygon there (`"kind":"custom"`) |
| `data/info.js` | editorial text per place, and the regions (`REGIONS`; `away: true` marks one outside the Bay Area, with its state for map links) |
| `data/subareas.js` | sections inside each place (built from `data/subareas_{sf,bay,south,eastbay,north,vegas}.json`): a seed point plus a line, drawn as Voronoi cells clipped to the boundary |
| `data/landmarks.js` | the landmark glyphs |
| `tools/build.js` | merges `data/subareas_*.json` into `data/subareas.js` and writes `dist/artifact.html`, the single-file page for the Claude artifact (flat map only: the 3D map's files are left out) |

## Data

On the hosted site the log is shared: one record per secret key in a Firebase Realtime Database (`js/sync-config.js` holds the database URL, `js/sync.js` talks to it over REST with no SDK), with the key carried in the `?log=` part of the link you bookmark and a copy kept in `localStorage`. Open a link with a key on another phone and that phone joins the same log. There are no accounts: each device can give a name (asked once, before its first write; changed under Settings; kept in `localStorage`), which goes on the spots it logs and on a small activity feed beside the log at `logs/<key>-ev`. Opening the app shows what the other devices added since this one last looked, at the top of the logbook; changes made while it is open arrive as a toast. There is no server, so nothing is pushed while the app is closed. The database rules allow reads and writes only below a key, never a listing. Inside the Claude artifact the log is one shared document for everyone the artifact is shared with. Boundaries: SF Planning Department (San Francisco neighborhoods); everywhere else in the nine Bay Area counties, US Census TIGERweb generalized (1:500k, shoreline-clipped) incorporated places and census-designated places, with Census counties for the land between places and the coast. The Las Vegas Strip: a ribbon along the TIGERweb road line of Las Vegas Boulevard, 700 m to the west and 1,100 m to the east, cut at Desert Inn Road, between the Venetian and Harrah's, Harmon Avenue and Tropicana Avenue. High points: Mapzen/AWS terrarium elevation tiles (zoom 12). Place search: Photon, © OpenStreetMap contributors. Street maps: OpenFreeMap tiles, © OpenStreetMap contributors, drawn with MapLibre GL JS.
